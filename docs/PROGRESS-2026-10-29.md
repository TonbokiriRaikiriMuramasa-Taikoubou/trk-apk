# trk! Android版：進捗整理（2026-10-29）

対象はtrk 1.1.4／trk214を基にしたAndroid開発版。**実機試験と正式配布は未実施**。ビルド・モック・エミュレーターの成功を、物理端末での音声やBluetoothの合格とは扱わない。引継ぎの正本は [HANDOFF](HANDOFF.md)、次の手順は [作業一覧](NEXT-ACTIONS-2026-10-29.md)。

## 直近の変更と確認範囲

- `ACTION_AUDIO_BECOMING_NOISY` の受信時、通常／逆再生、シンセの押鍵と余韻、予約済み測定音、ゲームSE、FX残響の停止を試みる。再接続だけでは再開しない。JS凍結、通知未到達、Androidの音声ルート切替のタイミングや未管理のアドオン音声に対する完全な漏れ防止は保証できない。
- API 26以上のrenderer終了でネイティブ復旧画面を試作。再生成時の自動再生ガードも実装。`chrome://crash` を2回発生させた[API 35エミュレーター検査](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40782607596)（`bdb6807`）は成功したが、実機、PiP中の終了、全データ・実音声は未検証。noisy通知はpluginからの模擬であり実broadcastではない。
- `npm run check` は **769件成功／37スイート**、`npm run cap:sync` 成功。jsdom／偽AudioNodeは実音声を再生していない。[debug APK CI](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40821563129)（`2aaa85f`）成功。[意図同期案のAPI 35検査](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40821563098)ではpause直後の非再生表示と偽再生主体の状態が食い違う反例を確認。[共有Future案のAPI 35 CI](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40818360528)（`650d2e0`）も成功したが、先行リスナーによる古い状態の観測と途中結果の表示遅延を確認した。途中の[CI失敗](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40817902173)は原因未特定。[Media3契約のAPI 35エミュレーターCI](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40815605797)で、古い応答の拒否と複数Future取消中の同期再入の反例を確認。Media3が製品debug runtime依存にないことも確認。[API 35エミュレーターCI](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40810902152)で、FX復旧の例外を注入して警告・再生抑止・再試行を確認した。実broadcast・実音声・物理タッチではない。
- この資料のソースZIPはAPKではない。APKは各GitHub Actionsの成果物で、保存期限とdebug署名に注意し、既存データを削除する前にバックアップを確認する。

## 次の優先事項

1. [実機チェック表](ANDROID-DEVICE-CHECKS.md)で機種・OS・WebView・APKコミットと、有線／Bluetoothの実音声・切断・再接続・通知・PiPを記録。既存データは消さず、テスト用データを使う。
2. FX再構築失敗時の再生停止・再試行案内を試作した。実機がない間はrenderer／出力切断の競合・ライフサイクルと回帰試験を継続する。保護できない場合に無音側へ倒す方針を維持する。
3. Media3段階Aの偽Bridge・偽Playerによる検討をさらに進め、実通信の取消・期限、セッション重複、サービス起動制限、Audio Focusを実装前に詰める。WebView停止後の再生継続は橋渡しだけでは保証できない。
4. SAF・共有の設計、権利・署名・配布条件を順次整理。ゲーム画面の向き、アプリ終了後の自動再開、正式アプリID、東方なし構成などは利用者と後で判断する。
