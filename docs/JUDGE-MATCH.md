# 🥁 MANUAL の判定の対応づけ（設計メモ・trk99）

> 対象：利用者の報告「上級以降の密な連打（3連など）で、1回の打鍵が横のノーツを巻き込む」。
> 実装は `js/judge-match.js`（純関数 `matchManualInput`・`window.Trk.judge`）、検査は `tests/judge-match.test.mjs`。
> 現在の状態・実機で未確認の項目は [上流の引き継ぎ](HANDOFF-UPSTREAM-trk214.md)（§2.3・§7）が正。利用者向けの説明は [`guide/play.md`](guide/play.md) §「🥁 MANUAL の判定のしくみ」。

---

## 1. 症状と原因

判定幅（`js/data.js` の `DIFFS`、標準。「判定の厳しさ」で ×1.3／×0.75）と16分の間隔：

| 難易度 | PERFECT | GOOD | | BPM | 16分の間隔 |
|---|---|---|---|---|---|
| 初級 | ±50ms | ±120ms | | 120 | 125ms |
| 中級 | ±42ms | ±105ms | | 140 | 107ms |
| 上級 | ±36ms | ±95ms | | 160 | 94ms |
| 達人 | ±30ms | ±80ms | | 174 | 86ms |
| RUSH | ±28ms | ±75ms | | 200 | 75ms |

上級以降の16分は GOOD 幅とほぼ同じ間隔なので、**隣のノーツの判定幅が重なる**。これは太鼓の達人（可 ±75ms）でも同じで、幅そのものは問題ではない。

問題は trk98 までの打鍵の割り当て（本書では **旧方式 `"ordered"`**）：「`nextIdx` から見て、判定幅内でいちばん早い未判定ノーツを1つ選ぶ。色が違えば MISS」。この規則では、次のどれか1回で以降が連鎖する。

```
譜面  ド@0   カ@86   ド@172  カ@258   （上級・GOOD ±95）
打鍵  （ドを落とす）カ@86   ド@172  カ@258   ← 2つ目以降はぴったり

旧方式  カ@86  → 幅内でいちばん早いのは ド@0（d=86）。色違い → ド MISS
        ド@172 → いちばん早いのは カ@86（d=86）。色違い → カ MISS
        カ@258 → ド@172 が色違い → MISS。最後の カ も残って MISS   ⇒ 4つとも MISS
```

きっかけは「1個落とす」「早すぎる空振り（幅の外）」「両手打ちの2打目」「順番の入れ替わり」のどれでもよく、密な区間が続く限り正しい打鍵が前の色違いノーツに吸われ続ける。太鼓さん次郎の仕様メモにある「巻き込み」、osu!（stable）の notelock と同じ構造。

## 3. 採用した規則（既定 `"smart"`）

`matchManualInput(chart, nextIdx, lane, now, w, policy)` は `nextIdx` から時刻順に未判定ノーツを見て、`null`（空振り）か `{ idx, kind, delta, wrongLane }` を返す。`game.js` の `handleInput` はその1件だけ `judgeNote` に渡す。判定幅・`sweepMisses`・PERFECT✦ の条件は変えていない。

1. `d = now − time` が `−GOOD` より小さくなったら打ち切り（これより先は全部まだ遠い）。`d > GOOD` のノーツ（幅を出たが `sweepMisses` が未処理）は無いものとして飛ばす。
2. **同じ色**のノーツに出会ったら：それより前に見た色違いの未判定ノーツ `prev` が無いか、`now ≥ prev.time` なら **そのノーツに当てる**（|d| ≤ PERFECT で PERFECT、それ以外 GOOD）。`now < prev.time` なら届かないので打ち切り（後ろの同色も届かない）。同じ色の中では旧方式と同じ**早い順**。
3. 同じ色が見つからなかったら色違いの打鍵。いちばん早い色違いノーツ `firstOther` について、`d ≥ −PERFECT` なら **MISS（`wrongLane: true`）**、`d < −PERFECT`（PERFECT 幅より早い）なら **空振り**（`null`）。
4. 飛ばした前のノーツは、幅を出たときに `sweepMisses` が MISS にする。幅内ならあとから叩いて拾える（順不同の救済）。

打鍵の種類ごとの結果（上級・16分 86ms の例）：

| 打鍵 | 旧方式 | smart |
|---|---|---|
| ド カ ド の 1つ目を落とし、カ・ドをぴったり | ド MISS → カ MISS → ド MISS（連鎖） | ド MISS、カ PERFECT、ド PERFECT |
| 1つ目を 100ms 早く空振り、以降ぴったり（ドカドカ） | 4つとも MISS | 1 MISS、残り PERFECT |
| 同色 4 連を 45ms 遅れで | 全部 GOOD | 全部 GOOD（同じ） |
| 隣り合うド・カの順番が入れ替わる（両方幅内） | 先の打鍵が前のノーツを MISS | 両方 GOOD |
| 両手打ち（同色の2打目が 10ms 後） | 2打目が次の色違いノーツを MISS | 2打目は空振り |
| 色違いをノーツの時刻ちょうどに | MISS | MISS（同じ） |
| 色違いをノーツの 37ms 以上前に | MISS | 空振り |
| 色違いの直後（幅内）に同色が続くとき色違いを押す | 前のノーツ MISS | 後ろの同色に届く（早い GOOD）。前は幅を出たら MISS |

## 4. 採らなかった案

| 案 | 理由 |
|---|---|
| 判定幅をきつくする／上級以降だけ厳しくする | 原因（割り当て）を直さない。普通のばらつき（σ25ms）で MISS が増えるだけ。「きびしめ判定」（×0.75）で既に試せる |
| 精密モード（PERFECT 付近だけ有効。それ以外は空振り） | 同上。幅が狭まるぶん連鎖は減るが、GOOD を取れる打鍵を全部捨てる。ランク判定との整合も新たに要る |
| 同色で「いちばん近い」ノーツに当てる（StepMania 式） | 遅れ気味の打鍵（+45ms など）が次のノーツへ飛び、前のノーツが MISS になって以降が1個ずつずれる。早い順なら全部 GOOD で済む |
| 同色の短い連打を無視する（デバウンス 15〜25ms） | 正しい速い連打（RUSH の 75ms 間隔・両手交互）まで食う。両手打ちの2打目は「早すぎる色違いは空振り」で十分に消える |
| 到達の境界を「前のノーツと後ろのノーツの中点」にする | lazer より早く前のノーツを見捨てる。lazer の境界（前の時刻）が、前を拾い直せる余地を最も残す |
| 後ろを叩いたら前を即 MISS にする（lazer の `MissForcefully`） | trk! の `sweepMisses` は幅を出た時点で MISS にするので結果は同じで、幅内なら拾える余地が残るぶん優しい。コンボ切れの表示も遅れない |
| 方式を記録に印として残す（chartGen の「旧方式」のように） | 両方式とも精度は同じ打鍵なら同じで、新方式は不当な MISS を減らすだけ。mod ではなく、記録の扱いを分けない |

## 5. シミュレーション

方法：合成曲 `longRamp`（`tests/helpers/synth.mjs`、174BPM）の自動譜面（chartGen 2・Seed 834271）に、プレイヤーモデルの打鍵列を当てる。ばらつきは正規分布、落としは一様乱数、両手打ちは 8〜28ms 後の同色2打目。`sweepMisses` と同じ条件で幅を出たノーツを MISS にする。「不公平 MISS」＝正しい色を ±PERFECT で押したのに MISS になったノーツ。6 seed の平均。数値の再現は `tests/judge-match.test.mjs` ③の `simulate` と同じ手順（テストでは 2 seed・閾値だけを見る）。

**上級（2083 ノーツ・P36／G95）** — MISS ／ 不公平 MISS ／ 最大連続 MISS ／ 最大コンボ

| 手 | 旧方式 | smart |
|---|---|---|
| 正確 σ15ms | 0.0 / 0.0 / 0 / 2083 | 0.0 / 0.0 / 0 / 2083 |
| 普通 σ25ms | 19.0 / 2.8 / 2.0 / 672 | 0.7 / 0.0 / 0.7 / 1884 |
| 荒い σ35ms | 99.2 / 12.8 / 3.3 / 166 | 18.3 / 0.2 / 2.2 / 461 |
| 35ms 早め σ20 | 7.0 / 1.3 / 2.2 / 1067 | 3.0 / 0.3 / 1.3 / 1203 |
| 3% 落とす σ20 | 84.5 / 30.2 / 5.2 / 134 | 56.5 / 4.5 / 1.5 / 134 |
| 両手打ち 20% σ20 | 258.8 / 0.5 / 7.0 / 77 | 10.7 / 0.0 / 1.2 / 607 |
| 全部（σ25・落3%・両手10%・15ms早め） | 188.8 / 34.2 / 6.5 / 75 | 69.0 / 3.5 / 1.8 / 144 |

**達人（2847 ノーツ・P30／G80）**：普通 σ25 35.7 → 4.7、荒い σ35 260.0 → 84.5、35ms 早め 209.3／58.8／**34連続** → 34.3／0.3／1.8、両手 20% 449.3 → 14.5。
**RUSH（3253 ノーツ・P28／G75）**：普通 σ25 48.7 → 12.8、35ms 早め 375.8／89.7／24.8 → 73.0／0.0／2.0、両手 20% 490.2 → 15.8。

読み方：
- 正確な手はどちらも 0 MISS。まばらな譜面（間隔 > GOOD 幅）は両方式で結果が同じ。
- smart の不公平 MISS はほぼ 0。残るのは「落とした直後の同色の連打が1個ずつ後ろにずれる」場合で、MISS の数は落とした数と同じ（連鎖ではない。§4 の「いちばん近い」を採らない代償）。
- 判定の平均・ばらつき（リザルトの統計）は悪化しない。両ボタン連打（mash）で得をする余地は旧方式と同じ（色違いは MISS のまま）。

## 6. 設定・互換性

- ❓謎設定「🥁 判定を昔のやり方にする」＝ `settings.judgeOrdered`（既定 `false`。`prefs.judgeOrdered === true` のときだけオン）。`resetAllPrefs` で `false`。Export／Import は `all` に含まれる。`?safe=1` は触らない（`escNoReturn` と同じ扱い）。文言は `judgeOrdered`／`judgeOrderedHint`（4言語、`js/i18n-options.js`）。
- `policy:"ordered"` は trk98 までの `handleInput` と同じ結果を返す（検査済み）。未知の方式名は `smart`。
- ランク判定・記録・称号は両方式で同じ扱い（mod ではない）。
- ORBIT／STAGE／TRUCK／CATCH は別の判定（`modes.js`／`stage.js`／`truck.js`／`catch.js`）で、変更なし。AUTO も変更なし。
- 読込順：`js/media.js` → `js/judge-match.js` → `js/game.js`（`index.html`）。`tools/check-repo.mjs` の `TRK_REGISTRARS` に `judge`。

## 7. 実機で見るところ・調整点

- 上級以降の16分（ドカド・トリル・3連）で、①1個落としたあと連鎖しない、②色違いは MISS のまま、③同色の連打で遅れ気味でも1個ずつ進む、④謎設定で旧方式に戻り、再読み込み後も保持され、リセットで戻る、⑤リザルトの統計が不自然でない。
- 手触りが合わないときの最初の調整点は、**色違いの空振り境界**（`firstOtherD < −w.perfect` → `null`）。PERFECT 幅より厳しく／ゆるくするなら、§5 の「両手打ち」と「色違いをちょうどに」の両方を見ながら決める。
- 同色の「早い順」を変える（StepMania 式）前に、§4 の理由を読む。
