# 楽曲名の表記ゆれとカタログ照合

更新：2026-10-15（trk167）。音源を解析して曲を識別する機能ではなく、端末内の曲名・照合メモとカタログの見出しを比べる機能です。

## 埋め込みテキストタグの表示名（trk167）

表示名の優先順を更新しました：**🎶 ユーザー設定名（曲のプロフィール）→ 🏷 埋め込みタグ（TIT2/©nam/TITLE 等）→ カタログ曲名（東方ThemeDB等）→ 元ファイル名**。`js/library.js` の `songDisplayTitle` がこの鎖を担い、曲リスト・検索・名前順の並び替え・選曲バナー・メディアプレーヤー・Media Session（ロック画面）・お気に入り／ゲーム履歴の表示に反映されます。

**カタログ照合は変わりません**：`plWish` 系の照合キー（`plTitleKeys`／`plSongMatchKeys`／装飾救済）と照合メモは、これまでどおりファイル名側（`it.base`／`it.title`）とプロフィールのアーティストを使います。タグは照合キーに一切関与しないので、タグがファイル名と食い違うファイル（タグが「Untitled」等）でも自動追加の挙動は変わりません。共有プレイリストにもタグは乗りません（曲ファイル・譜面を含まない既存ルールそのまま）。

タグは**読み取り専用**です：`js/audio-art.js` の `extractTags`（ID3 TIT2/TPE1/TALB/TPE2/TRCK/TCON＋v2.2 の TT2 等、MP4 ©nam/©ART/©alb/aART/trkn/©gen、FLAC/Ogg の TITLE/ARTIST/ALBUM/ALBUMARTIST/TRACKNUMBER/TRACKTOTAL/GENRE）で表示用に読むだけで、書き戻し経路（`createWritable` 等）は存在しません＝タグ編集はしない方針のままです。読み込みは一覧の行が見えたとき（サムネイルと同じ IntersectionObserver）と選曲時。結果はメモリにだけ保持し、リロード後は読み直します（正はファイルの中にあるので、別の場所に複製してズレた表示を出しません）。アルバム別／アーティスト別のグルーピング表示とトラック番号順の並びは次段です（PLAYER-ROADMAP #16 に記録）。

## 今回の例と原因

- カタログ：`Symphony No.5 - I. Allegro con brio`
- 利用者提供のMusopen掲載名：`Symphony no. 5 in Cm, Op. 67 - I. Allegro con brio`
- 出典として提示されたページ：<https://musopen.org/music/2567-symphony-no-5-in-c-minor-op-67/>

従来は区切り・拡張子・先頭のトラック番号を揃えるだけだったため、`in Cm, Op. 67` の有無を吸収できませんでした。trk155では、ページの現状・ダウンロード後の実ファイル名・音声タグは再確認していません。別名の根拠は利用者の提示した文字列であり、独立したサイト確認済みの記録ではありません。

## 採用した方法

1. **根拠のある別名をカタログへ**：既存の `matchAliases`（最大8件）に配布名を登録。短い紹介名と正式な配布名の対応を、利用者が一曲ずつ設定する代わりにカタログ側で持ちます。表示名・ファイル名は変えません。
2. **意味を変えない正規化**：`js/title-match.js` でクラシックの形式名・作品番号・ローマ数字の楽章を認識できる曲名には追加キーを作ります。`No.5`／`No. 5`／`No5`、`Op.67`／`Op. 67`、カンマ・コロン・ダッシュ・アンダースコア、`in Cm`／`in C minor` などを揃えます。短調の略記は今のところ `in Am`〜`in Gm` の単音名だけで、異名同音や他言語への翻訳はしません。
3. **同一性を示す情報を残す**：調・作品番号・楽章番号・速度記号・編曲等の副題は消しません。クラシックの構造を認識した見出しでは `作品名 - 楽章` の左右単独への分割を止めます。普通の `Suguri - BELIEVE` は従来のまま。数字だけの末尾（例 `.67`）を拡張子として落とす既存の問題も修正しました。
4. **保存済みの棚にも届ける**：個別に取り込んだカタログは従来の更新経路を使用。複数カタログを集約した `cat: "trk:classic"` の Classic Vol.1 は通常の更新経路に入らないので、タイトル・アルバム・アーティストが同じ項目の別名だけを補います。順序、所持曲、名前、配置、フリーズ状態、利用者が変えた曲名はそのままです。既存の起動時更新で行い、一回限りの移行フラグは増やしません。

ファイルは送信・改名せず、音源同梱・音声指紋・外部検索APIも追加していません。実音源の曲名が提示された文字列と異なる場合（数字IDだけ、演奏者や録音年が付く等）は、今回の別名だけでは照合しないことがあります。

## どこまで保証するか

- 今回登録したのはBeethovenの交響曲第5番・第1楽章の別名1件です。Classic全曲の配布名調査を完了したという意味ではありません。
- 作品番号・楽章等が異なる、または「I. Allegro con brio」だけ・「Symphony No.5」だけのファイルは今回の項目に一致させません。
- 短いカタログ名そのものと一致する従来のファイルは引き続き認識します。曲名にない作曲者・演奏者・版まで推定するものではありません。
- 通常の曲名一致における同名の複数録音の選択は従来どおり（アルバム → アーティスト → 最初の候補）。trk156の装飾除去による救済だけは、複数候補があれば未確定のままにします。録音の同一性まで保証しません。共有プレイリスト取り込みは別の既存ルール（一意な候補・指定されたファイルサイズ）を維持します。
- 自動追加は従来どおりフリーズ中には行いません。別名の更新はカタログメタデータの更新であり、凍結した所持曲リストを増やす処理ではありません。
- Node/VMテストでは提示名・拡張子・先頭番号・記号・短調表記の一致、誤一致の拒否、既存Classicへの反映を確認。`tools/e2e-title-match.mjs` ではヘッドレスChromium 153と合成WAVで、保存済みClassicの更新、曲追加→灰色から所持行への変化、選曲・デコード、別作品番号／楽章の拒否、フリーズ尊重、モバイル幅、再起動を確認しました。ページ例外は0（未生成の任意OST manifestの404だけ別記録）。**Musopenの実ダウンロード音源・PC／Android実機・実際のフォルダ選択・音の聴取は未確認**です。

## 装飾と版の切り分け（trk156）

ブルアカの例を使い、**表示上の飾りだけを限定的に吸収し、言語・長さ・編曲等の情報は残す**方針にしました。音質・音源の正体を解析した判定ではありません。

| ローカルの名前（例） | 判定 |
|---|---|
| `Daily Routine 247.m4a` | 従来どおりDaily Routine 247に一致 |
| `【高音質】Constant Moderato.m4a` | Constant Moderatoに一致。Daily Routine 247とは別曲 |
| `🎧Theme 22 - Daily Routine 247 by Nor.m4a` | Daily Routine 247とカタログのアーティストNorに一致 |
| 上と同じ曲名で `by KARUT` | 一致させない |
| `【高音質】Constant Moderato Piano Arrange.m4a` | Piano Arrangeの項目だけに一致。原曲には一致させない |
| `【高音質】Daily Routine 247 (Short).m4a` | 版名なしの項目には一致させない |
| `[Unknown] Daily Routine 247.m4a` | 未対応。未知の括弧を勝手に削らない |

### 実装範囲

- 先頭の `【高音質】`、`[HQ]`、`[High Quality]`、🎧を許可リストとして扱い、その後の `Theme 1〜4桁の数字 -`（区切りは `-`／`–`／`—`／`:`）を除く追加キーを作ります。カタログの順番とTheme番号が同じだとは仮定しません。**曲名本体の247は残します。**
- 括弧全般、絵文字全般、任意の番号、任意の先頭文字列は削りません。未知の装飾や順序は一致しないことがあります。
- `by`以下をローカル名から切り落としません。カタログの完全な曲名（登録済み別名を含む）と、そこへ ` by アーティスト` を足したキーと比べます。したがって曲名の一部かもしれない **`by angel` を一律に削らない**ままです。アーティストの翻訳・別名・推測はしません。飾りのない単独の `曲名 by 作者` も今回の救済の対象外です。
- 通常の曲名・登録済み別名・利用者の照合メモが優先。装飾除去は `plWishMatch` の最後で全候補を集め、**1ファイルだけなら採用、複数なら未確定**とします。以前にプレイリストへ入った曲や手動追加済みの曲は削除しません。
- 専用キーを区別して保持するので、共有プレイリスト取り込みの照合は緩めません。表示名・元ファイル・保存済みメタデータも書き換えません。照合ロジックの更新なので、既存ブルアカリストの取り込み直しや移行フラグは不要です。

### JP・CN・Short・Instrumental

`Do you wanna kiss by angel` と提示された5種類（JP Ver.／JP Ver. (Short)／CN Ver.／CN Ver. (Short)／Instrumental Ver.）は、**同じ楽曲の異なる版として区別する**のが安全です。今回は「どれか1つで全版を所持済みにする」扱いにはしていません。

- `JP`／`CN`／`Ver.`／`Short`／`Instrumental`等を含む見出しは、`曲名 - 版名` の左右単独で当てないようにしました。版名は消さず、同じ版の完全な名前とだけ照合します。
- 版名のないタイトルからJP・フル尺等を推定しません。`JP Ver.`だけのファイルも、どの曲か分からないので自動では当てません。括弧の配置や未知の版名など、未対応の表記は残ります。
- **trk156時点では、この曲はブルアカOST Vol.1〜8の225曲カタログに見当たらず、利用者の提示名を仮想wishとして検査しました。** trk157では公式配信・PVを確認し、正式名 `Do you wanna kiss angel` の確認済み5項目を別リストに追加しました。Short2版は未収録です。旧仮想テストの `by angel` を正式名や別名にしたわけではありません。
- 提示された参考リンク：<https://bluearchive.fandom.com/wiki/Do_you_wanna_kiss_angel>。コミュニティWikiであり、公式の配信・権利情報ではありません。trk156時点ではページ本文を未確認として扱いました。後続の案内先調査ではページ本文・公式bilibili・TapTap・Apple Musicを取得でき、正式名 `Do you wanna kiss angel` と配信3曲／PV2本を確認しています。確認済み5項目のプレイリストを追加し、詳細とShort2版の未確認事項を [`BLUEARCHIVE-MIKA-MUSIC.md`](BLUEARCHIVE-MIKA-MUSIC.md) に記録しました。
- trk157では公式の曲名・版・入手先を確認し、**版ごとにカタログの別項目**を作りました。「どの版でもよい」という作品単位の収集表示は、録音単位の照合とは別の機能として検討します。

検査：`tests/title-match.test.mjs` でブルアカ実カタログ225曲との照合、5版の総当たり、誤一致の拒否を確認。`tools/e2e-title-match.mjs` で実アプリへ合成WAVを追加し、ブルアカVol.1の対象2曲が所持行になること、作者違いの拒否、元の名前維持をヘッドレスChromiumで確認しました。購入音源・YouTube由来の実ファイル・m4aのデコード・実機での聴取を確認したものではありません。

## 次の改善候補

| 方法 | 判断 |
|---|---|
| 配布元の曲名をまとめて調査して別名を増やす | 最優先。曲単位で出典・楽章を確認し、成功例と誤一致のテストを足す。ページ見出しと実DL名は分けて記録する |
| `Op.`・調・楽章を一律に取り除く | 採用しない。似た名前の別作品・別楽章まで所持済みになり得る |
| 編集距離・単語の重なりで自動確定 | 採用しない。短い曲名、別楽章、編曲版の誤一致を招く |
| 自動確定できない曲を候補一覧で利用者がまとめて対応付け | 将来候補。候補と確定を区別し、端末内だけに対応を保存するUIが必要。今回は未実装 |
| 音声タグ（作品・作曲者・楽章）や音声指紋による識別 | 別課題。データの信頼性、演奏違い、処理量、プライバシーを検討してから。今回は未実装 |

未対応の名前は、当面は曲プロフィールの「カタログ照合メモ」にカタログの曲名全体を書くことで、表示名を変えずに補えます。

## 媒体条件（trk157）

ミカ曲の5項目は `matchMedia`（audio／video）を保存し、通常一致・別名・装飾付き救済のどれも媒体が合う候補だけを採用します。動画取込の確認flag→実FileのMIME→実ファイル名の拡張子の順で判断し、曲名やプロフィール上の表示名では音声をPV扱いにしません。媒体不明は未一致。媒体条件のない既存項目は従来どおりです。内容を聴いて判断する仕組みではなく、言語・録音・誤ったファイル形式情報を検証するものでもありません。
