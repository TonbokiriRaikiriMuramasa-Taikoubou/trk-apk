## UX 方針（暫定）

- 下部は **ライブラリ／エフェクト／再生／書斎／ゲーム**。VLC のように動画と音声を別のトップ階層に分ける代わりに、trk の曲・動画・プレイリストをライブラリに集約する。既存のプレイリスト単位のタブはその中に残す。
- ライブラリを初期画面とし、右側のゲーム準備はゲームを選んだときだけ表示。TV とバナーのスペクトラムは通常画面から隠し、スペクトラムの設定は残す。
- 再生は既存の音楽・動画プレイヤー、書斎は既存のリーダーを開く。プレイヤーの「ゲームモードへ」で現在選択中の曲を引き継ぎ、既存の譜面生成・難易度・PLAY の画面へ戻る。曲未選択や読み込み中は、上流と同じく PLAY は無効。プレイヤー退出時の再生継続・停止は上流の設定に従う。
- `🐔trk's playlist` はチュートリアル完了時や起動時に自動生成せず、設定の選択欄から必要なリストを個別に追加する。カタログの新項目は自動的に選択肢へ現れる。既存リストは維持し、削除したリストも個別に選んで追加できる。音源は別途入手が必要（内蔵デモを除く）。カタログ由来の既存リストの曲目を起動時に上書きしない。
- 設定内のシンセモードは初期オフ。「シンセモードを使用する」をオンにすると、ライブラリのエフェクトドックの電源を長押しして開ける。既に保存された旧設定は尊重するため、旧版で有効状態として保存された人は引き続き有効。音声設定の初期化ではオフに戻る。
- 設定の各欄は初回は閉じる。利用者が開閉した状態は端末内の `trk_apk_settings_panels_v1` に保存し、検索による一時的な開閉は記録しない。この表示状態は独立したローカル情報で、設定バックアップには含まれない。全設定の初期化では消える。
- 取り込みの5操作は「コンテンツを追加」の中に畳む。再接続・再スキャンは必要な場合だけ別に表示する。Android版はまだ MediaStore の自動収集も SAF のネイティブ実装もないため、操作の完全削除やアクセス確認の省略はできない。ファイル取り込み・保存先の案内も畳んだ中に残す。
- エフェクト画面では既存の TrkFX プリセット、5帯域EQ、TrkTV の色調プリセットを操作する。選択内容は既存の設定と連動し、再生中の動画・全画面動画の canvas に色調を適用する（走査線等のオーバーレイはゲーム画面向け）。より詳しい音の設定を開く場合はプレイヤーを閉じる。
- プレイヤー内に同じ下部ナビを配置し、エフェクトを選んでもプレイヤーを閉じずに音と再生位置を維持。動画プレビューも表示し、再生／一時停止して調整できる。プレイヤーに戻すとプレビューを元の位置へ戻す。ゲーム・ライブラリなどへ出る場合は既存のプレイヤー退出設定に従う。動画の全画面表示中は、まず全画面を閉じる。
- 選曲・設定画面は実寸で表示し、ゲーム中は上流の 1920×1080 ステージのスケーリングを使う。書斎では既存の閉じる操作を使い、モーダルの上にナビを重ねない。
- 画面向きは通常は端末設定に従う。右下ボタンで現在の向きを一時固定／解除し、10秒長押しで緊急復帰を確認する。ゲーム画面の方針は実機評価後に決める。このナビも小さい画面・横向きで要評価。
- タイトル右上のアンテナで裏画面の再生継続（試行）と一時停止を切り替える。画中絵はプレイヤーに設定を設け、初期オフ、オン時の既定は動画のみ。音楽も含めると曲名とアプリアイコンを表示。ゲーム中は除外する。PiPと再生はAndroidで未検証、OSや省電力で中断し得る。

### 調査根拠

- Android Developers の [Layouts and navigation patterns](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)：コンパクトな画面のナビゲーションバーには同階層の 3〜5 項目を置き、大きな画面ではレールなどを検討する。現在は大画面でも幅を制限した下部バーを使用しており、レールは未実装。
- [VLC for Android の操作ガイド](https://www.vlchelp.com/android-complete-guide/)：ビデオ・オーディオ・参照・プレイリスト・その他と再生画面を分けている。trk のプレイリスト中心の構造に合わせ、分類をそのまま複製しない。
- Android の [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)：ユーザーがフォルダを選び、アプリが許可を永続化してアクセスする。フォルダの移動・削除や権限変更で再選択が必要になり得る。現実装は Web のファイル選択であり、SAF の永続 URI ブリッジは未実装。
- [Android 13 のメディア権限](https://developer.android.com/about/versions/13/behavior-changes-13) は音声・動画などの種類別。インストール時に許可するだけで任意の文書・パックや全フォルダへの永続アクセスが得られるわけではなく、実行時の許可や選択が必要。権限を拒否・変更した場合も取り込みや再接続の入口が必要。
- Android の [Media3 再生アプリ](https://developer.android.com/media/implement/playback-app)：バックグラウンド再生には MediaSessionService が推奨される。現実装にはネイティブ再生サービスがない。

## 開発・ビルド

要件：Node.js 22 以上、npm、Android Studio、Android SDK 36、JDK 21（Capacitor 8）、端末またはエミュレーター。SDK と依存物の取得にインターネットが必要。

```sh
npm ci
# vendor の build / dist が欠けている場合は npm run vendor:update で復元
npm run vendor:update
npm run check
npm run cap:sync
npm run cap:open:android
# または Android SDK と JDK を設定後
cd android
./gradlew assembleDebug
```

`android/` は生成済みなので `cap:add:android` を再実行しない。Web ソース変更後は `cap:sync` が必要。`mobile-web/` と `android/app/src/main/assets/public/` は生成物で Git 管理しない。Debug APK は `android/app/build/outputs/apk/debug/` に生成される。配布には署名・バージョン・アプリ ID・権利とプライバシーを別途確認する。署名鍵は Git に入れない。

## 制限とリリース前の確認

- GitHub Actions上でdebug APKのビルドとJavaコンパイルは成功した（コミット `aa02acc`）。この作業環境には JDK / Android SDK がない。**Android WebView、実機、音声出力・動画・描画・タッチ・回転・Android 戻る操作は未検証。** debug APKは正式配布版ではない。
- Android ファイルピッカーによる個別選択、フォルダ選択、再起動後の再接続、IndexedDB の容量・保存は機種依存。既存のフォルダ共有機能は WebView で動く保証がない。SAF 対応が必要。
- WebView の再生は通知、画面消灯、バックグラウンド、Bluetooth、オーディオフォーカスで保証されない。上流には画面非表示時にプレイヤーを一時停止する処理がある。Media3 化は今後の設計課題。
- 音源選択から譜面生成・再生・ゲーム開始、再生→エフェクト→再生時の音声・映像・位置・音量、プレイヤー→ゲーム、書斎の編集保存・復帰、設定や各種モーダル、縦横・安全領域を実機で確認する。
- `docs/android.md` はこのガイドへの案内に整理済み。`release/README-upstream-web.txt` は上流Web版の配布スクリプト用でありAndroid APKの案内ではない。
- `INTERNET` は実機での検証前なので残す。FileProviderはCapacitorの画像キャプチャが使うため残し、外部パスをアプリ固有の Pictures に限定した。
- アプリ用 `docs/` の削減は未実施。ガイドやクレジットから他の資料へのリンクを確認し、リンク切れを防いでから行う。初回遅延調整は機種別の実測とUX設計が必要。
- `npm audit` は開発用 Capacitor CLI の `xcode` → `uuid` に moderate の指摘がある（2026-10-28）。本番依存のみの監査では指摘なし。依存を一方的にメジャー変更せず、上流の更新と互換性を確認する。

### 今回の検証範囲

`npm run check`（上流の検査、追加ナビゲーションの DOM 単体テスト、実際の trk スクリプトを読み込む jsdom 結合スモーク）を実行。DOM テストは画面遷移・選曲維持・プレイヤーからのエフェクト切替・映像プレビューの復元・プリセット／EQへの接続・言語表示を検証するが、実ブラウザーのレイアウト、音や Android 端末を検証するものではない。ローカル HTTP 配信は 200 を確認。ブラウザー自動テストはこの環境の Chromium 実行に必要なシステムライブラリがなく未実施。

### 初回レビュー反映（2026-10-29）

- `@capacitor/app` を追加し、ネイティブ戻るを段階的に処理。戻るでデータ削除やゲーム再開をしない。実機、未知のモーダル、回転時、画面ロックや外部アクティビティ復帰は未検証。
- Android側で既存の同スコープSWを解除し、バージョン別シェルキャッシュのみ掃除。既に制御中なら一度だけ再読み込み。Web/PWAのSWは維持。アプリの共有インテント受信は未実装。
- `allowBackup=false`、鍵除外、モーダル中のナビ抑止、浮動ボタン位置、主な初回ボタンの44px化を実装。サイズとOSバックアップ動作は端末で検証する。
- Lat式ミクは同梱しない。作者の配布先を案内し、利用条件は各自確認する。モデルの選択・表示はAndroid実機未検証。その他の共有素材のストア利用、ゲーム画面の向き、Media3、アプリIDは未決定。遅延タップ補正、Web資産のdocs削減、ネイティブSAFは今後の検討。
