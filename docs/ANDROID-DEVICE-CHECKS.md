## 実機テストの準備

1. GitHub Actionsの成功した `Android debug build` 実行ページで、対象コミットの `trk-apk-debug-…` 成果物をダウンロードして展開する。`app-debug.apk` と `SHA256SUMS.txt` が入っている。GitHubへのサインインが必要な場合があり、成果物は7日間で失効する。
2. ダウンロード後に `sha256sum -c SHA256SUMS.txt` 等でAPKのハッシュを確認する。取得元とコミットを確かめ、テスト用端末・データでのみインストールする。Androidが提供元不明アプリの許可を求める場合は、信頼できる取得元を確認し、必要な操作が終わったら許可を戻す。表示された警告を無条件に無視しない。
3. CIのdebug鍵はランナーごとに変わり得るため、別ビルドを上書きインストールできない場合がある。既存アプリの削除・データ消去はユーザーデータを失うので、先にバックアップを書き出し、内容を確認する。別署名のインストールは既存データを保持したまま強制しない。
4. 手元の音源・動画を使う場合は、著作権と個人情報に注意し、テスト素材やログを公開しない。下記の記録欄を複製し、未実施の項目を成功扱いしない。

補助的に `.github/workflows/android-emulator-smoke.yml` でAPI 35エミュレーター上の起動・Backキー・向き固定ブリッジ・PiP比率の計算と橋渡しを自動確認する。[実行結果](https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk-apk/actions/runs/40755872214)（`2db4f58`）では明示的なネイティブPiP開始とWebViewへの通知も成功。エミュレーターのJSクリックは物理タッチや10秒長押し、Bluetooth、音声、自動PiPや映像表示、機種固有動作を証明しない。

## M1：基本スモーク（全項目未実施）

- [ ] 新規起動、初回案内、設定パネルが閉じていること、シンセ初期OFF、5タブの表示と操作。端末回転・安全領域・小さい画面。
- [ ] 音楽・動画の複数ファイル選択、キャンセル、再生、曲切替、シーク。利用可能な場合はフォルダ選択・再起動後の再接続も試す。失敗した場合は端末選択UIと経路を記録。
- [ ] 再生したままエフェクトを変更し、映像・音声・音量・位置に意図しない変化がないこと。プレイヤーとゲーム準備の移動。
- [ ] プレイ開始・入力・停止・結果・選曲復帰を5モード（通常の叩く、TRUCK、ORBIT、STAGE、CATCH）それぞれ確認。音／譜面のズレ、タップ反応・描画の引っ掛かりを記録。
- [ ] 戻る操作：初回案内、モーダル、書斎、設定、プレイヤー、ゲーム中／一時停止／結果、終了確認。ジェスチャーナビの予測型戻るも観察し、誤操作・意図せぬ終了がないこと。
- [ ] 向きボタンの固定・解除、端末設定に従う既定動作、プレイ中・一時停止・結果画面・モーダル・書斎での非表示と選曲復帰後の再表示。
- [ ] タイトルで10秒長押し→確認画面→キャンセル、その後の短押し。改めて10秒長押し→承認→復帰。指を離す・領域外へ動かす・OS割り込みでは誤発動しないこと。WebViewの長押しメニューやpointercancelの発生も観察。**黒画面の復帰が必要な場面でも到達できるか**（ゲーム中はボタン非表示のため戻る操作も含む）を評価する。セーフモード承認は映像・TV設定を変更するので、テスト用データで行う。
- [ ] アンテナON／OFFそれぞれでホーム移動・復帰、画面ロック・解除、外部ファイルピッカー、他アプリと通話による割り込み。OFFは一時停止、ONは継続を試みる現状だが、OSによる停止はあり得る。シンセ発音や長押しシーク・ループ中にも移動し、帰ってから音や操作が押しっぱなしにならないか確認する。TVの無音プレビューも確認。
- [ ] PiPの初期OFF、動画のみON、音楽もON、対応しない／失敗した場合、PiPから復帰・終了、戻る操作。PiP設定ONかつアンテナOFFでホーム移動→すぐ復帰→再度ホーム移動を繰り返し、前回の待ち時間が次の移行を途中で停止しないか確認。アンテナONでもPiP非稼働の通知や復帰操作で再生が意図せず止まらないか確認。縦・横・極端な比率の動画で枠と映像の収まりを確認（極端な比率はOS許容範囲へ丸める）。音楽表示、再生中状態と通知、アンテナとの組合せ。PiPの専用再生／停止ボタンは未実装。
- [ ] 書斎への取り込み・閲覧・復帰、設定と曲一覧の再起動後の状態、アプリを終了した後の挙動。
- [ ] Androidのクラウドバックアップと端末間移行：**テスト用の端末・アカウント・データだけ**で、OSの移行操作後にアプリの保存データがコピーされないかを確認。手動で書き出したバックアップは別扱い。移行元のデータを消去しない。OS／メーカー固有ツールの結果も記録。
