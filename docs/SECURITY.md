# 🛡 セキュリティ（脆弱性の洗い出しと、その後の守り）

trk! は **サーバーを持たない** ブラウザ音ゲーです。アカウント・広告・行動分析はなく、曲も書斎の本も端末の外へ出ません。
そのぶん攻撃面は「**他人が作ったファイルを読み込むところ**」「**ブラウザに入ってくる他人のコード**」「**端末に貯まる私物**」に集中します。
この文書は 2026-10-06 に **色々な側面から一度しっかり洗い出した** 結果と、そこで塞いだ穴、残した仕様、これからの推奨をまとめたものです。

- 自動で見張るのは `tools/check-security.mjs`（`npm run check` に含まれる）。
- 仕様として残したものは「**なぜ残すか**」まで書いてあります。**見つけた穴は隠さず、直したうえで記録する**のがこの文書の方針です。

---

## 0. 標準の脆弱性リストとの突き合わせ

定番のリスト（**OWASP Top 10 Client-Side Security Risks**／**CWE Top 25 2025**）に1項目ずつ当てはめた一覧は **`docs/SECURITY-CHECKLIST.md`** にあります（✅確認済み／🟡仕様／🔶未実施の推奨／➖対象外）。この文書は「trk! で実際に見つけたものと直した記録」です。

## 1. 前提（trk! のなりたちと、守るべきもの）

| 項目 | 中身 |
|---|---|
| 配布 | 静的ファイル（GitHub Pages）。ビルド無し。Android は Capacitor の WebView に入れた同じ一式（任意のチュートリアル用オリジナル音声フォルダーは削除可能） |
| 保存 | `localStorage`（設定・記録・お気に入り・アドオン）+ IndexedDB（パック・曲・VRM/MMD・書斎の本・解析結果のキャッシュ） |
| 外部通信 | **同一オリジンの取得のみ**（VRM/MMD のライブラリも `assets/vendor/` に同梱。外部オリジンへは出ません。任意デモは小さな manifest を確認し、MP3 は選択時のみ読み込みます） |
| サーバー | 無し。trk! へ送信する処理は無い（送る機能を作らない） |
| 守るべきもの | ①端末内の私物（書斎の本・画像・曲・スコア・設定）②「入れたつもりの無いコード」を動かさないこと ③壊れないこと（データ消失・フリーズ） |

## 2. 信頼の境界（どこまで信じて、どこから検証するか）

| 入力 | 扱い | 検証 |
|---|---|---|
| 本体のコード（このリポジトリ） | **信頼する** | GPL / レビュー / `npm run check` |
| `assets/vendor/` の three.js・three-vrm・three-mmd-loader（自前ホスティング・F-5） | **信頼する（固定）** | `tools/vendor-lock.json` の SHA-384 を `npm run check` が毎回照合。第三者オリジンからは読まない |
| 共有ファイル：パック `.stpack`、譜面 `.shadow-taiko.json`、プレイリスト `trk-playlist`、エフェクト `trk-fx`、TVスキン `trk-tvskin`、スキン `.skin.json`、⭐ `trk-favs`、記録 `shadow-taiko-records`、公認 `verified.json` | **信頼しない** | 形式・範囲・https・パス・容量を検証してから使う |
| PWA の OS 共有受け口（`share_target` の POST） | **送り元を区別できない**（他サイトのフォームからも届きうる） | 一時受信後、ファイル名・件数・注意を示して取り込み前に確認。拒否時は一時 inbox を削除。形式検証は既存経路へ |
| 🧩 アドオン（`.js` / `.trk-addon`） | **入れた人の責任**（＝ページ内でフル権限のプログラム） | 同意の文言・サイズ上限・安全モードでの停止 |
| 端末の保存（localStorage / IndexedDB） | **ユーザーの私物だが、改ざんされうる** | 読み込み側で毎回かたちを整える |
| URL（`?safe=1` `?reset=…` `?tv=…` `#…`） | **誰でも作れるリンク** | できることを限定し、危ないものは確認や明示を要求（§5） |
| ファイル選択・フォルダ共有 | ユーザーが明示的に選んだもの | 元ファイル／入力フォルダは**読み取り専用**。書斎の明示的なテキストコピー書き出しだけは、別途選んだフォルダへ衝突しない新規コピーを作成（既存ファイルは上書きしない） |
| 覚えてあるフォルダのハンドル（IndexedDB `shadow_taiko_library` の `share` / `dir`） | 便宜のため保存するが、**ページ内コードから読める**（＝アドオンも読める） | 「🚫 共有をやめる」で両方削除。⚠ 権限の取り消しはブラウザ側 |

## 3. 洗い出しのやり方

1. **静的走査**：危ない書き方（`eval` / `new Function` / `document.write` / `srcdoc` / 素の `innerHTML` / `target=_blank` の rel 漏れ / `href` への直代入）を全部数える。
2. **検証コードの読み合わせ**：共有ファイルを読む関数を、形式・型・範囲・パスの4点で確認。
3. **動的確認**（jsdom ハーネスをリポジトリ外で実行）：`javascript:` の名刺 URL、`__proto__` 入り設定、宣言サイズを偽った ZIP、安全モード、リセット経路などを実際に流す。
4. **自動の見張り番**：洗い出しで見つけた「守り」を `tools/check-security.mjs` に固定し、`npm run check` で毎回検査（戻ってきたら FAIL）。

- 動的コード評価は **`js/addons.js` の `runCode()` にある間接 `eval` 1か所だけ**（ユーザーがファイルを選び、同意したアドオンを動かすため。サンドボックスではなく、同意前には走らない）。`new Function` / `document.write` / `srcdoc` は **0 件**。`tools/check-security.mjs` はこの1か所だけを許可し、ほかの評価シンクを拒否する。`innerHTML` は結果画面の1か所だけで、**すべて `esc()` を通した**テンプレート。

## 5. 仕様として残したこと（と、その理由）

1. **アドオンは「入れた人の責任」**：ページの中のフル権限で動くプログラムです（ブラウザ拡張やユーザースクリプトと同じ考え方）。だから
   - 入れるのは**ファイル選択（または同梱の `js/addons/○○.js`）だけ**。パック・プレイリスト・譜面などの共有ファイルから**勝手にインストールされる経路は無い**。
   - `?safe=1` では**読み込まない**（入れたものは消えない）。
   - コード512KiB／入力ファイル4MiBの上限。ファイルから生JavaScriptとして受けるのは `.js` だけ（`.json` 等は形式検証）。入れたアドオンは一覧から**オフ／削除**できる。
2. **スコアはローカルの記録**：端末を持っている人は書き換えられます。「書き換え不可能なランキング」ではないので、そこを前提にした機能は作りません。
3. **共有プレイリスト（他人から受け取るファイル）で起きること・起きないこと**：楽曲ファイルも譜面も含まず、**コードも実行しない**（JavaScript は一切入っていない）。相手ができるのは
   - 曲名・アーティスト名などの**見出しを偽ること**（あなたの手持ちの曲と同名にすると、その曲として表示される＝**なりすまし**。取り込むかどうかは自分で選べる）
   - コメント・タグ・投稿者名で**文章を表示させること**（いずれもテキストとしてのみ表示・長さ上限あり。HTML としては解釈しない）
   - **https のリンクを踏ませること**（開く前に必ず確認ダイアログ。§F-1/F-14 の関所つき＝フィッシングの可能性はゼロではない）
   - 大量の曲名を並べること（1000曲・タグ5個・フォルダ/プレイリスト数に上限）
   つまり**「だます」ことはできても、「コードを動かす」「あなたのファイルを読む」ことはできない**、が設計です。
4. **破壊的なリセット URL の扱い**：`?reset=all`／`?reset=factory`／`?reset=full` と `#reset=all` は**確認ダイアログ**を挟みます（踏んだだけでは消えません）。確認を飛ばせるのは query の `?reset=all&force=1` または hash の `#reset=all&force=1` のように、`force` の値が厳密に `1` の場合だけです。`force=0` や `forcely=1` は確認を省略しません。`?reset=tv|audio|notes|lite|keys|amp` は影響が限定的なので、これまで通り即効です。⚠ **`?factory` 単体は全リセットではなく `?safe=1` と同じセーフモード**です（`js/addons.js` の `safeNow()` が昔から `sp.has("factory")` をセーフ扱いにしており、`js/core.js` の「`?factory` で入る」というコメントとも一致）。壊す動作にしない側へそろえてあります。全リセットは `?reset=all`／`?reset=factory`／`#reset=all`。
5. **アドオンの同意は「実行の前」**：新規導入は同意ダイアログ → 同意 → コード実行 → 保存の順です。保存済みアドオンは起動時に指紋を先に照合し、不一致ならコードを実行しません。記録のない旧アドオンは互換性のため動かしますが、警告を出します。localStorage 内の同意記録は同一ページのコードから書き換えられるので、署名やサンドボックスではありません。
6. **非常口はワンタップのまま**：`?safe=1` や `?reset=tv|audio|notes|lite|keys|amp` は「映像が変になった」「音が壊れた」ときの逃げ道なので、**即効**を優先しています（消えるのは設定だけで、記録・パック・書斎の本は消えません）。`?reset=all` だけは被害が大きいので確認を挟みます（§5-4）。

## 6. これからの推奨（未実施・検討中）

1. **CSP は「基本は入れない」方針**（2026-10-06 決定）：trk! は**ビルド無しのHTML/JS**で、inline の import map と blob のメディアを多用します。CSP を入れると開発中（ローカルファイル・`file://`・Capacitor）の検証が止まりやすく、壊れたときの切り分けも難しくなります。**安定版としてリリースするときだけ**、外部化した import map＋ハッシュ＋`media-src blob:` を実機テスト付きで検討します（いまは `<meta http-equiv>` も置きません）。導入する場合の出発点：
   `default-src 'self'; script-src 'self'; img-src 'self' blob: data:; media-src 'self' blob:; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'`
   （第三者オリジンがゼロになったので `https://cdn.jsdelivr.net` は不要になりました。inline の import map を外部ファイル化するかハッシュを付けるのが先です）
   **Referrer-Policy** は現行の主なブラウザ既定を前提に、現時点の脆弱性とは扱いません。安定版の再評価時に、GitHub Pages と Capacitor/WebView の実際の配信・遷移で送信される情報を確認し、明示設定の必要性を判断します。
   ⚠ **アドオンとのトレードオフ**：`js/addons.js` のユーザー選択アドオン実行には間接 `eval` が1か所あります。この例の `script-src 'self'` はそれを止めるため、CSPを有効にするとアドオン機能は動きません。機能を保つためだけに `'unsafe-eval'` を足すとCSPのXSS防御を弱めます。導入時は「アドオンを無効化／宣言型へ変更」か「制限を受け入れ、CSPをXSS防御の強い境界と見なさない」かを先に決めます。
2. **`mobile-web/` から開発用文書を除外**（`docs/HANDOFF.md` など。Capacitor の成果物を軽くする）。
3. **GitHub Actions の SHA 固定**（`actions/checkout@<sha>`）。
4. **配信側のヘッダ**：`Content-Security-Policy: frame-ancestors 'none'` や `Permissions-Policy` は、Cloudflare Pages など配信側を挟む場合に設定（HTMLのメタタグでは書けない項目）。

## 8. 同梱した第三者コードを確かめる（`assets/vendor` と `tools/vendor-lock.json`）

three.js／three-vrm／three-mmd-loader は **`assets/vendor/<package>@<version>/…` に同梱**してあります（100ファイル・4.98MB）。入口の `import()` から `import` の連鎖を辿り、WASM やテクスチャのような**実行時アセット**（`new URL("…", import.meta.url)`／`new URL('…', import.meta.url)`）まで含めたコピーです。

```
node tools/check-vendor.mjs               # オフライン検証：記録とのハッシュ一致・相対importの解決・import mapの被覆
node tools/check-vendor.mjs --source=npm  # 同じグラフを npm レジストリのタール玉から読んで突き合わせる（来歴の確認）
node tools/check-vendor.mjs --list        # 同梱物の一覧（出どころのURL・サイズ付き）
npm run vendor:update                     # 版を上げるとき：取得し直して import map と lock を書き換える
```

オフライン検証は **`npm run check` の中に入っています**（ネットワーク不要）。`--source=npm` は npm に届く環境で来歴を確認するためのものです。同梱ファイルは**手で編集しない**でください（編集した瞬間に検査が落ちます）。

**2026-10-06 の再点検**：取り込み道具と検査がどちらもダブルクォートの import だけを拾っていたため、three.js の `./three.core.js` と GLTFLoader の `../utils/BufferGeometryUtils.js`（シングルクォート）が本番配布物から欠け、旧検査も8項目PASSのまま見逃していました。両方の引用形式を後方参照で抽出し、`new URL(..., import.meta.url)` は import map を使わずファイル相対アセットとして検査します。逆テストで対象ファイルと lock 記録を外すと、旧検査はPASS、新検査は missing edge でFAILすることを確認しました。`npm run vendor:update` はローカル import map の正規化とローカルパスの二重変換も修正し、再実行可能にしています。
