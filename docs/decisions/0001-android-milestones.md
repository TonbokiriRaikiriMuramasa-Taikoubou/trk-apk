# Android開発の進め方（2026-10-29）

状態：開発上の暫定方針。実機確認まで各マイルストーンを完了としない。

## 決定と理由

- M0：クリーン環境で `npm ci`、`npm run check`、`cap:sync`、`assembleDebug`。Javaやリソースを含めて継続的にビルドを確かめる。debug APKはGradleの**debug鍵で署名**された開発専用で、リリース用の署名なし成果物ではない。秘密情報や公開用署名鍵は不要。CIの実行・成果物の保持はリポジトリのActions設定に依存する。
- M1：[ANDROID-DEVICE-CHECKS.md](../ANDROID-DEVICE-CHECKS.md) を用いて実機スモーク。M2：確認で見つかった不具合を修正。タップ校正は実測後に設計する。
- M3：Media3による背景再生とShokz操作。既存Web再生・FX・解析・譜面同期を壊さない方式をまず検討し、WebView主体のブリッジが実測で不足する場合に限って聴取専用ネイティブ再生を検討。Media3は未実装であり、この案だけで背景継続は保証できない。詳細は [media3-plan.md](../media3-plan.md)。
- M4：SAF等のファイルアクセスと共有。大きな動画のシークに必要な範囲アクセスや権限喪失を設計・検証する。M5：署名鍵の安全な管理、ライセンス・素材・ソース公開条件の確認と配布。
- 共通コードの正本は上流trk。Android固有は可能な限り `apk-*`、`android/`、Capacitor設定へ置き、共通箇所の変更を必要な差し込み口に抑える。既存の改変を一度に移し替えるより、自動・実機回帰を確保してから段階的に整理する。

## 採らなかった案・リスク

- ビルドを待たずにMedia3・SAFへ進める案：Javaやリソースの不具合を検出できないため、まずビルド基盤を優先。
- WebViewから一斉にExoPlayerへ切り替える案：FX・MIDI・解析・譜面と切り離される恐れがあるため、採らない。
- 未知のモーダルの任意ボタンをBackで押す案：削除・承認を誤発火し得る。キャンセルを明確に識別できる仕組みと実機検証が整うまで、未知のものは現状どおり安全側で消費。
- D2D転送を黙って許可する案：アプリ内に保存した私的データが想定せず引き継がれ得るため、現段階はクラウド・端末間ともに除外する設計。利用者が移行したいデータは明示的なバックアップ機能を使う。OS・メーカー製移行ツールの挙動は実機未確認。

## 後で決めること

作業ブランチでのGitHub Actionsによるdebugビルドは利用者の了承を得た。プロセス終了後の自動再開、配布先（GitHub／Play等）、正式appId、東方なしビルドの要否は決定後に記録する。Google PlayでFGSを使う場合は申告要件も確認する。
